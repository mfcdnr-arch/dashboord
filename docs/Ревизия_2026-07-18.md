# Ревизия проекта Dashboard — 2026-07-18

Проверка готового функционала на соответствие установленным правилам и целям.
Метод: живой стек (API `/health` = ok, 48 маршрутов), разбор кода фронта/бэка,
проверка «графичности» создания дашбордов и удобства для 4 ролей.

Ориентир (правила): CLAUDE.md + рабочие правила в памяти. Три «максимума» —
система максимально **информативная**, **автоматизированная**, **удобная** для
администратора / модератора / аудита / обычного пользователя. Особый фокус —
создание дашбордов **максимально в графическом виде**, система сама предлагает
варианты из выпадашек (документы/поля/столбцы/показатели/формулы).

## 1. Соответствие правилам — сводная оценка

| Критерий | Оценка | Комментарий |
|---|---|---|
| Проверка по ходу (e2e+браузер, tsc/build 0) | 🟢 сильно | Применяется системно на каждой фиче |
| Ревью после каждой доработки | 🟢 сильно | Даётся с рисками и предложениями |
| Не перегружено | 🟢 ок | Решения простые, модульные |
| Графичность создания ФОРМУЛ | 🟢 сильно | `FormulaBuilder`: элементы (агрегат/ячейка/метрика/число) + действия +−×÷, всё выпадашками, живой предпросмотр |
| Графичность создания ВИДЖЕТОВ | 🟡 средне | Форма из выпадашек (тип/источник/датасет/поле/мультиполя), НО нет живого предпросмотра при сборке и нет «подсказок что собрать» |
| Информативность (прозрачность KPI) | 🟡 средне | Есть drill (формула+первичка), алерты, ключевые KPI; НЕТ владельца/свежести/качества данных на виджете, нет текста-пояснения модератора |
| Автоматизация | 🟡 средне | Есть авто-сборка дашборда из объекта, авто-распознавание таблиц; НЕТ планировщика обновлений, авто-подсказок метрик |
| Удобство АДМИНИСТРАТОРА | 🔴 слабо | Нет UI управления пользователями/ролями/отделами (заводили через SQL) |
| Удобство МОДЕРАТОРА | 🔴 слабо | Раздел «Модерация» не реализован; публикация «в эфир» не привязана к approve |
| Удобство АУДИТА | 🔴 слабо | Раздел «Отчёты» не реализован; входы не логируются; нет «кто/когда/что смотрел» |
| Удобство ПОЛЬЗОВАТЕЛЯ-просмотрщика | 🟡 средне | Дашборд смотрится, drill есть; НЕТ киоска, избранного, поиска, чистого read-only режима |

Вывод: **ядро данных и конструкторы (объекты→документы→датасеты→метрики→дашборды)
сделаны качественно и достаточно графично**. Главные пробелы — **весь контур
администрирования/модерации/аудита** (разделы «в разработке») и **добивка
графичности/информативности конструктора дашбордов**.

## 2. Что уже сильно (не ломать)

- **Конвейер данных**: объект → папки → документы → авто-распознавание таблиц →
  маппинг → выпуск датасета (`dataset_release`). Автоматизация ввода есть.
- **Конструктор формул** — эталон графичности: сбор мышью, выпадашки полей/строк/
  дат/метрик, живой предпросмотр значения, версии/статусы.
- **Движок подсказок** `/metrics/data-sources` уже отдаёт по датасетам: объект,
  папку, документ, даты, поля (с типом), строки — основа для любых выпадашек.
- **Дашборды**: авто-сборка из объекта, шаблоны/клон, drag-drop сетка, мультисерии,
  cross-filter, версии+публикация, PDF, KPI-алерты, RLS, фильтры+пресеты,
  редактирование виджета, виджеты-аннотации.
- **Прозрачность (drill)**: из чего собран показатель — формула + первичные строки.

## 3. Пробелы и предложения по доработкам (по приоритетам)

### A. Графичность и информативность конструктора дашбордов (главный фокус)
1. ✅ **Живой предпросмотр виджета при сборке/редактировании** (СДЕЛАНО 2026-07-18) —
   `POST /widgets/preview` + панель «Предпросмотр» в форме; рендерит виджет (в т.ч.
   графики ECharts) на лету по конфигу без сохранения.
2. ✅ **Панель-каталог источников при сборке** (СДЕЛАНО 2026-07-18) — компонент
   `SourceCatalog`: документ→датасет (с родословной 📄 документ·папка·объект) →
   поля/столбцы (с типом) → строки → периоды + список метрик. Клик-перенос в виджет
   пока не сделан (эксплорер; вставка покрыта выпадашками и подсказками).
3. ✅ **Подсказки «что собрать»** (СДЕЛАНО 2026-07-18) — `GET /widgets/suggestions`
   + панель `SuggestPanel`: под выбранный датасет предлагаются готовые виджеты
   (KPI/график/динамика/сравнение/план-факт/таблица), выбор галочками → пакетное
   добавление.
4. ✅ **Метрика в выпадашке — с подсказкой** (СДЕЛАНО 2026-07-18) — `list_data_sources`
   отдаёт unit+formula лучшей версии; в форме опции «name · ед» + строка-подсказка
   «ед.: X · формула: <DSL>» под выпадашкой.
5. ✅ **Формула прямо из виджета** (СДЕЛАНО 2026-07-18) — KPI-виджет с `config.formula`,
   источник «Формула» + встроенный `FormulaBuilder` + текстовое поле; считается на
   лету движком метрик без создания метрики. **Волна A закрыта.**
6. **Фильтр по объекту** и стабильная выпадашка категории (сейчас категория —
   выпадашка из строк датасета, но при пустом кэше падает в ручной ввод).

### B. Контур администрирования / модерации / аудита (крупнейший функциональный пробел)
7. **Модуль «Пользователи» (§2c)** — UI: создание пользователя (ФИО-поля + **Отдел
   из справочника** `departments`), назначение ролей, блокировка. Сейчас — только
   через SQL. Плюс справочник отделов.
8. **Аудит входов** — таблица `login_events` (кто/IP/agent/успех/время), запись в
   `/auth/login`, отчёт «кто заходил, сколько раз».
9. **Модуль «Модерация»** — очередь дашбордов «на проверку» → approve → публикация;
   правило «в эфир только после approve» (сейчас не enforced, §7.7). Конфликт
   интересов (не одобряешь своё) — уже есть в метриках, распространить на дашборды.
10. **Отчёты по посещаемости** — какие дашборды смотрят, рейтинг популярности,
    диаграмма просмотров (нужен лог просмотров `view`).

### C. Информативность и «прозрачность показателя» (декомпозиция из CLAUDE.md)
11. **Расширенная инфо-карточка показателя** — владелец, периодичность обновления,
    свежесть данных («данные на дату X»), качество/достоверность, и **текст-
    пояснение модератора** (необязательное поле; если пусто — «Информации нет, в
    разработке»). Пожелание 7. Сейчас drill даёт только формулу+первичку.
12. **Значок свежести данных** на виджете (стыкуется с §7 приоритет 3).

### D. Обычный пользователь и вывод
13. **Режим-витрина/киоск** (полный экран + автопрокрутка для ТВ в холле) — §7 п.2.
14. **Экспорт Excel/PNG** — §7 п.2.
15. **Избранное / недавние / поиск** по дашбордам на «Главной» — §7 п.3.

### E. Автоматизация и надёжность
16. **Планировщик обновления данных** (периодический ingestion) + свежесть.
17. **Батч-эндпоинт данных страницы + TTL-кэш** (сейчас N запросов на страницу) — §7 п.3.

## 4. Рекомендованный порядок

Две волны, обе двигают к «современной, многофункциональной, интуитивной» системе:

- **Волна «Графичность дашбордов» (фокус заказчика):** A1 живой предпросмотр →
  A3 подсказки «что собрать» → A2 каталог источников → A4 подсказки метрик →
  A5 формула из виджета. Быстрая видимая отдача, прямо про «собрать мышью».
- **Волна «Управление системой»:** B7 Пользователи+отделы → B8 аудит входов →
  B9 Модерация → B10 отчёты посещаемости. Закрывает роли админ/модератор/аудит.

Затем — «прозрачность показателя» (C11–12) и вывод (D13–15).
