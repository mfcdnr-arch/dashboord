# Руководство администратора Dashboard

> Документ для администратора/эксплуатации системы. Здесь фиксируются
> административные возможности, эксплуатационные процедуры и **осознанно
> отложенные функции** (что и почему пока не реализовано, что нужно для
> реализации). Обновляется по мере развития проекта.

Кодовое имя: `dashbord`. Отображаемое имя: «Dashboard». Целевая среда:
Astra Linux SE / LAN / часто офлайн. Развёртывание — см. [ДЕПЛОЙ.md](ДЕПЛОЙ.md).

---

## Роли и разграничение доступа (кратко)

- **superadmin** — владелец системы, стоит выше admin. Два права принадлежат
  только ему:
  - **одобряет собственную работу** — свою версию формулы и свой дашборд.
    Это исключение из разделения обязанностей: пока в организации нет второго
    сотрудника с правом модерации, иначе довести показатель до статуса
    «одобрена» было бы невозможно вообще. Самоодобрение не замалчивается —
    оно отмечается в журнале аудита, а у версии показателя автор и одобривший
    совпадают;
  - **удаляет дашборды, показатели и выпуски данных**, а также документ
    вместе с выпущенными из него данными — все эти операции необратимы,
    поэтому остальным ролям кнопки удаления не показываются.
- **admin** — полный доступ: пользователи, отделы, роли, объекты, метрики,
  дашборды, аудит, справочники. **Удалять дашборды и показатели не может**
  (только суперадминистратор); ему доступны обратимые действия — снять
  с публикации, отправить в архив, завести новую версию формулы.
- **moderator** — как admin по контенту (объекты/метрики/дашборды/модерация),
  без управления пользователями; редактирует формулы, но **свою** версию формулы
  одобрить не может (разделение обязанностей), и удалять дашборды и показатели
  тоже не может.
- **senior_moderator** — привилегированная роль просмотра (видит всё как admin/
  moderator при разрешении доступа).
- **user** (обычный пользователь) — видит только выданные ему дашборды
  (опубликованные) и созданные им самим; данные ограничиваются RLS.
  В меню у него остаются **«Дашборды»** и **«Кабинет»** (плюс «Витрины», если
  ему доступна хотя бы одна): рабочие инструменты — «Объекты», «Метрики»,
  «Главная» — скрыты, поскольку все действия в них всё равно требуют прав
  модератора. Зрителю доступны просмотр, фильтры, drill «🔍 подробнее»,
  выгрузки (PDF/Excel/PNG), режим «📺 Витрина» и «💬 Обсуждение».

Слои разграничения доступа, уже реализованные:
1. **RLS дашбордов** — непривилегированный видит дашборд только по гранту и
   только опубликованным (модерационный гейт).
2. **RLS виджетов (widget-level)** — гранты на отдельные виджеты внутри дашборда
   (миграция 004); при наличии хотя бы одного виджет-гранта зритель-по-гранту
   видит только выданные виджеты.
3. **RLS строк данных (row-level)** — видимость строк датасета по подразделению
   (миграция 024, экран «🔐 Доступ к строкам» у объекта); фильтруются виджетные
   чтения датасета, именованные метрики остаются объективными.

## Разделы интерфейса (что где)

| Раздел | Кому виден | Назначение |
|---|---|---|
| **Главная** | admin/moderator | сводка, счётчики, «Данные в системе» (документы, выпуски, период отчётов, последняя загрузка), «С чего начать» — путь из шести шагов на новой установке (исчезает, когда всё пройдено), витрина KPI (набор настраивается кнопкой «Настроить»), число дашбордов на проверке, уведомления |
| **Объекты** | admin/moderator | объекты → папки → документы; конструктор разметки листа «как в Excel» (область данных мышью, снятие лишних строк/столбцов, транспонирование, режим отдельных ячеек), «↻ Распознать заново», выпуск датасетов, канонические поля, «🔐 Доступ к строкам» (row-level RLS), переименование и удаление объектов, папок и документов, блок «Выпущенные данные» в карточке файла — отмена и возврат выпуска, удаление выпуска; вкладка «📊 Аналитика папки» — свод показателей с приростом, состояние данных (ритм поступления, пропущенные отчёты названы датами, застрявшие файлы поимённо), что построено и что нет, сравнение объектов по одноимённым показателям |
| **Метрики** | admin/moderator | панель «Что можно посчитать по вашим данным» (предложения из анализа файла), библиотека готовых рецептов «📚 Готовые», конструктор и текстовый режим формул (DSL, см. [Инструкция_по_формулам.md](Инструкция_по_формулам.md)), версии draft → validated → approved (свою версию одобряет только суперадминистратор), автозаполнение описания показателя, удаление показателя (только суперадминистратор; система откажет, пока показатель используют виджеты или формулы других показателей, и назовёт их) |
| **Руководителю** | всем, у кого есть доступ хотя бы к одному отчёту подборки | подборка отчётов для руководства: на плитке до трёх главных цифр с приростом и подсветкой сработавшего порога. **Состав подборки ≠ доступ:** отметка отчёта его не открывает — доступ выдаётся отдельно, кнопкой «🔒 Предоставить доступ» под подборкой или из карточки сотрудника. Состав настраивается кнопкой «⚙ Настроить подборку»: система советует, что положить (опубликован, есть числовые показатели, есть описание, сколько раз смотрели), и отдельно называет мешающее, но ничего не запрещает — решает человек |
| **Дашборды** | всем (по грантам) | конструктор страниц и виджетов, переименование и описание дашборда (✎), карточка «ℹ О дашборде» (состав и источники цифр), фильтры периода/строки, пресеты, drill-down, экспорт Excel/PDF/PNG, обсуждение, доступ, «📁 Папка» (банк отделов), «В архив», удаление (только суперадминистратор; нельзя, пока дашборд опубликован, на проверке или входит в витрину), режим «📺 Витрина» (киоск для ТВ), кнопка «↕ Подогнать размеры» (ставит каждому виджету размер по его типу, состав страницы не меняет), фильтр списка по объекту → папке → отчёту («что построено на данных этого файла») |
| **Витрины** | staff всегда; зрителю — только если ему доступна хотя бы одна | именованная подборка из НЕСКОЛЬКИХ ЦЕЛЫХ дашбордов на одном экране («стена мониторов»); порядок — drag-and-drop |
| **Архив** | по допуску | помесячные слепки данных дашборда (переживают ретенцию и удаление дашборда), выгрузка в Excel из замороженных данных, автослепок 1-го числа |
| **Модерация** | admin/moderator | очередь заявок на публикацию, решение «одобрить/вернуть» с причиной и чек-листом, история |
| **Обращения** | всем | тред «пользователь ↔ администратор»; заблокированный пользователь может отправить обращение прямо с экрана входа. В очереди у каждого открытого обращения видно, сколько оно ждёт ответа («⏱ 3 ч»), а по истечении срока, заданного в «Настройках», — красное «срок вышел». Обращения, пришедшие кнопкой с виджета или запросом доступа, несут контекст: из карточки открывается сам отчёт или карточка доступа сотрудника |
| **Справочники** | admin/moderator | услуги и нормативные документы организации |
| **Пользователи** | admin/superadmin | учётки, роли, отделы, блокировка, сброс пароля, «📊 активность» (единый отчёт: входы + действия + комментарии), «🕵 грант на аудит» (выдаёт только superadmin) |
| **Аудит** | superadmin; admin — по гранту | журнал действий и журнал входов, экспорт CSV/XLSX |
| **Отчёты** | admin/moderator | здоровье системы (CPU/RAM/диск/сервисы, история самопочинок), бизнес-показатели, популярность, качество данных, модерация, посещаемость, логи сервисов (через Loki, если включён мониторинг) |
| **Настройки** | admin/superadmin | пороги свежести/ретенции, вход-блокировка, пороги CPU/RAM/диска, срок ответа на обращение (делает ожидание видимым в очереди), бэкап и автоархив («Запустить сейчас») — **без правки `.env` и рестарта** |
| **Кабинет** | всем | свой профиль, роли, история своей активности, смена пароля |

### Что делать с ошибочными данными

Загрузили не тот файл или разметили неверно — данные уже на дашборде.
Система различает три ситуации, и правило простое: **обратимое разрешено
свободно, необратимое — только суперадминистратору и с проверкой связей.**

| Что нужно | Где | Кому | Обратимо |
|---|---|---|---|
| **Отменить выпуск** — данные перестают использоваться дашбордами и формулами, но остаются в системе, файл не трогается | Объекты → файл → «Выпущенные данные» | admin/moderator | да, кнопка «Вернуть в работу» |
| **Удалить выпуск** — значения удаляются, **файл остаётся** и его можно разметить и выпустить заново | там же, кнопка 🗑 | только superadmin | нет |
| **Удалить документ вместе с данными** — исчезает и файл, и выпуски | Объекты → папка → 🗑 у файла → «Удалить вместе с данными» | только superadmin | нет |

**Почему отмена не блокируется, а удаление блокируется.** Отмена обратима,
поэтому она разрешена даже когда на данные опирается виджет: иначе сотрудник
с ошибочными цифрами на дашборде оказался бы заперт. Вместо запрета система
пишет, что именно останется без данных. Удаление необратимо — оно откажет и
назовёт виджеты и показатели поимённо.

**Важный нюанс.** Проверяется не выпуск сам по себе, а исчезновение
**последнего активного выпуска кода датасета**: виджеты ссылаются на датасет
по коду, а не на конкретный выпуск. При недельных формах под одним кодом
отмена одного выпуска ничего не ломает — дашборд считается по остальным.

### Оформление: три темы

Кнопка смены темы — в правом верхнем углу, между колокольчиком и «Выйти», а
также **на странице входа** (там же, в углу): тему можно выбрать до
авторизации, потому что выбор хранится в браузере и входа не требует.

Темы переключаются по кругу, каждое нажатие включает следующую:

| Темы | |
|---|---|
| **Светлая** | по умолчанию |
| **Тёмная** | для работы при слабом освещении |
| **«МинЭк ДНР»** | сине-золотая, заголовки шрифтом Oswald |

**Кнопка показывает значок СЛЕДУЮЩЕЙ темы, а не текущей** — то есть в светлой
теме нарисована луна («нажмите — станет тёмной»). Подсказка при наведении
говорит и текущую тему, и то, что включится. Выбор запоминается на этом
компьютере, у каждого пользователя свой, на других он не влияет.

Графики перекрашиваются вместе с темой: палитра вынесена в токены, жёстких
цветов в виджетах нет.

### Помощники, которые предлагает система

- **«✨ Собрать»** (Дашборды) — автосборка дашборда по объекту: **карточка на каждый числовой показатель формы** (по 4 в ряд; при очень широких файлах первые 24, остальные графы видны в таблице), график по строкам, динамика при нескольких периодах, общий график «Сравнение показателей» и таблица-первичка. Блок строится на каждый код датасета отдельно: выпуски с одним кодом складываются в ряд по датам, новый код начинает отдельный ряд.
- **«💡 Предложить ещё»** (внутри дашборда) — недостающие виджеты по датасету: система знает, что уже построено, и не предлагает это повторно.
- **«💡 Предложить метрики»** — черновики производных метрик (разница, доля, период-к-периоду, год к году, накопительный итог, план/факт, отклонение от цели). Принятие создаёт **черновик** метрики — дальше обычный цикл draft → validated → approved.
- **Аномалии на графике динамики** — статистическая отметка выбросов (отклонение от линии тренда более N σ, по умолчанию 2). Включается в форме виджета галочкой «Отмечать аномалии». Это статистика (метод наименьших квадратов + стандартное отклонение), **не ИИ**.
- **«📚 Готовые»** (Метрики → новая версия формулы) — библиотека из 20 рецептов: итоги, доли и проценты, план и факт, динамика, сравнение, цели. Пользователь выбирает рецепт и указывает столбцы выпадашками, формулу собирает и сразу проверяет сервер — знать синтаксис не нужно.
- **«Что можно посчитать по вашим данным»** (Метрики) — система разбирает названия столбцов распознанного файла и предлагает готовые показатели: выполнение плана и остаток, доли по воронкам, приросты, итоги. Связки ищутся и по самим числам, поэтому находятся пары, не предусмотренные словарём. **Каждое предложение перед показом вычисляется на реальных данных**: если формула не считается, предложение не показывается, а посчитанное значение выводится рядом с названием. При нескольких объектах под предложением указано, из какого файла взяты столбцы.
- **«✨ Заполнить автоматически»** (карточка метрики) — черновик расширенной информации о показателе: расшифровка формулы по-русски, источник данных, число загруженных периодов, единица измерения, состояние версии. Текст подставляется в поле, но **в базу не пишется** — проверяет и сохраняет модератор.

### Бэкап и восстановление

**Бэкап делается сам.** Ночной таймер (03:30) снимает дамп базы, архив
хранилища документов (MinIO) и ротирует старые наборы. Каждый дамп сразу
проверяется на восстановимость (`pg_restore --list`) — бэкап, который не
разворачивается, хуже отсутствия бэкапа, потому что создаёт ложное спокойствие.
Состояние и кнопка «Запустить сейчас» — в разделе **«Настройки»**.

**Восстановление делается из командной строки — и это сознательно.**
Кнопки «восстановить» в интерфейсе нет: одно случайное нажатие стирает всю
работу за период между снимками. Восстановление — редкая операция, которую
выполняет администратор сервера, понимая последствия.

```
ssh <пользователь>@<сервер>
cd ~/Dashbord
ls backups/                       # выбрать набор: YYYYmmdd-HHMMSS
./restore.sh backups/20260815-033000
```

Флаги: `--db-only` (только база), `--minio-only` (только файлы документов),
`--yes` (без подтверждения — для скриптов). Перед восстановлением скрипт
спрашивает подтверждение и называет набор, который будет развёрнут.

**Что важно знать заранее:**

- восстановление **перезаписывает** текущие данные: всё, что появилось после
  снимка, будет потеряно — при сомнении сначала снимите свежий бэкап
  («Настройки» → «Запустить сейчас») и только потом восстанавливайте;
- база и файлы документов восстанавливаются вместе, иначе на дашбордах
  появятся ссылки на файлы, которых нет в хранилище;
- после восстановления запустите `./deploy.sh` — он накатит миграции, если
  снимок сделан на более старой версии системы.

## Фильтр периода: что он делает на самом деле

Это поведение **изменилось 17.08.2026** — если вы читали прежнюю версию
руководства, перечитайте эту главу.

Фильтр «Период» над страницей дашборда **выбирает отчёт**: показывается
последний выпуск, попавший в выбранный диапазон. Не сумма за период и не
среднее — именно состояние на конец периода, как его зафиксировал отчёт.

- Поставили «01.07 — 31.07» — все карточки, таблицы, графики, полосы «план и
  факт», воронки и светофоры показывают **июльские** цифры, и каждая карточка
  подписана датой, за которую данные показаны на самом деле.
- **«Динамика» и «Год к году» работают иначе**: им нужен весь ряд точек, а не
  один выпуск, поэтому они получают диапазон целиком и просто обрезаются по
  его границам.
- Если отчётов за выбранный период **нет вовсе**, виджет так и пишет: «За
  выбранный период отчётов нет». Он не подставляет свежие данные — цифра не за
  тот период опаснее пустого места, потому что выглядит рабочим ответом.

Рядом с полями дат стоит быстрый выбор: 7 дней, 30 дней, прошлый месяц
(календарный), 90 дней, год.

> **Чем это было раньше.** До 17.08 фильтр периода действовал только на
> «Динамику» и «Сравнение источников». Все остальные виджеты читали последний
> отчёт и период игнорировали молча: человек ставил июль, видел прежние числа и
> либо решал, что данных нет, либо принимал августовскую цифру за июльскую.

### Свой фильтр виджета

У отдельного виджета можно задать собственный период (галочка «Свой фильтр» в
форме виджета). Он **перекрывает** фильтр страницы: виджет с собственным
периодом не меняется, когда меняют фильтр наверху.

### Страницы-срезы

Мастер сборки умеет делать страницы, привязанные к конкретной отчётной дате.
Их виджеты помечены «📌 срез за ДД.ММ.ГГГГ · не обновляется» и не меняются,
когда приходит следующий отчёт. Мини-график и прирост на таких карточках
обрезаны по дате среза — снимок не показывает то, чего на его дату ещё не было.

## Обратная связь: как до вас доходят проблемы

Раньше пользователь мог написать только из «Кабинета», и самым дорогим было
объяснить словами, ГДЕ проблема. Теперь есть три пути, и все они приводят
обращение к вам уже с контекстом.

### «⚑ проблема» на виджете

Под каждым виджетом есть кнопка. Человек выбирает вид проблемы одним нажатием
(неверная цифра / нет данных / непонятно, что показывает / ошибка), текст
необязателен. **Всё остальное прикладывает система:**

- название отчёта, страницы и виджета;
- что это за цифра — тем же текстом, что и подсказка ⓘ на экране;
- **значение, которое человек видел**, посчитанное тем же кодом, что рисует сам
  виджет;
- если виджет не считается — текст ошибки. Часто это и есть ответ на вопрос
  «почему у меня пусто», полученный до того, как вы открыли отчёт.

В карточке обращения у вас появляется кнопка **«Открыть отчёт →»** — переход
сразу на нужную страницу, без поиска по названию среди десятков.

Повторное нажатие по тому же виджету дописывает в уже открытое обращение, а не
заводит второе.

### «🔑 Нужен другой отчёт»

Кнопка в списке дашбордов у обычного пользователя. **Списка недоступных отчётов
система не показывает и не покажет** — даже названия говорят, какие показатели
за кем закреплены. Поэтому человек называет отчёт словами, а запрос приходит с
его именем; в карточке обращения у вас кнопка **«Выдать доступ →»** открывает
карточку доступа именно этого сотрудника.

### Срок ответа

В «Настройках» задаётся срок ответа на обращение (по умолчанию сутки). Сам по
себе он ничего не запрещает — он делает ожидание видимым: в очереди у каждого
открытого обращения стоит «⏱ 3 ч», а по истечении срока — красное «срок вышел».
Без этого очередь выглядит одинаково и на первом часу, и на третьи сутки.

Когда вы **впервые открываете** обращение, автор видит отметку «просмотрено» и
получает одно уведомление — до первого ответа его жалоба иначе выглядит так же,
как в момент отправки, то есть как будто ушла в пустоту.

### Ограничение

Один человек может завести не больше 10 **новых** обращений в час. Переписка в
уже открытом обращении не ограничена: замолчать человека посреди начатого
разговора нельзя.

## Аналитика папки объекта

Папка объекта — это одна форма, приходящая раз за разом. Вкладка
**«📊 Аналитика папки»** рядом со списком файлов отвечает на четыре вопроса
одним экраном.

1. **Что в цифрах** — свод всех показателей папки с текущим значением и
   приростом к прошлому отчёту, без открывания дашбордов.
2. **Можно ли данным верить** — сколько файлов дошло до данных, а сколько
   застряло (поимённо), ритм поступления формы и **пропущенные отчёты, названные
   датами** («не хватает отчётов за 22.06.2026»), а не общим «данные неполные».
3. **Что построено, а что нет** — какие показатели не показаны ни одним
   виджетом, и какие дашборды собраны по этой папке. Рядом кнопка «Добавить на
   дашборд»: забытые показатели можно вывести карточками, не заводя их вручную.
4. **Как объект на фоне других** — сравнение по одноимённым показателям.
   Сравнение идёт **по названиям**, а не по кодам: коды выводятся из заголовков
   конкретной формы и у другого подразделения свои.

Ничего не считается заново: значения берутся тем же способом, что и данные
виджетов, а ритм — тем же, что шлёт уведомления о пропущенном отчёте. Иначе
экран однажды разошёлся бы с дашбордом, и верить нельзя было бы обоим.

## Осознанно отложенные возможности (рекомендации)

Ниже — функции, которые обсуждались и **сознательно не реализованы** на текущем
этапе. Решение принято совместно с заказчиком. Для каждой указаны: суть, причина
отсрочки, предусловия и заметки для будущей реализации.

### 1. Рассылка отчётов (PDF) по расписанию на e-mail (SMTP)

**Суть.** Автоматическая генерация PDF дашборда/отчёта и рассылка получателям по
расписанию (например, ежедневно/еженедельно руководителям).

**Статус:** НЕ реализовано. Отложено.

**Причина отсрочки.** Требуется **рабочий SMTP-сервер МФЦ** (адрес, порт,
учётные данные/релей, политика отправки во внутренней сети / из закрытого
контура). На момент решения SMTP-инфраструктура заказчика недоступна, поэтому
функция блокируется на внешнем предусловии, а не на разработке.

**Что уже готово (фундамент).**
- Экспорт PDF/PNG дашборда на фронте (кнопки «⤓ PDF/PNG»).
- Экспорт данных страницы в Excel.
- Планировщик фоновых задач **arq** (Redis) уже используется (жизненный цикл
  данных: свежесть/ретенция/уведомления) — на нём же можно повесить cron-рассылку.

**Предусловия для реализации.**
- Параметры SMTP МФЦ: host, port, TLS/STARTTLS, логин/пароль или доверенный
  релей, разрешённый адрес отправителя.
- Согласование, кому и что рассылать (список рассылок, привязка к дашбордам/
  ролям/отделам), с учётом RLS: рассылка должна уважать права получателя (не
  отправлять данные, которых он не видит).
- Политика хранения сгенерированных PDF (в MinIO / временно).

**Заметки по реализации (когда появится SMTP).**
- Конфиг SMTP — через переменные окружения (`SMTP_HOST/PORT/USER/PASSWORD/…`),
  секреты в `.env.prod` (не в образ).
- Рендер PDF — переиспользовать существующий экспорт (или серверный рендер
  страницы, чтобы не зависеть от браузера получателя).
- Расписание — задача arq по cron; таблица «подписок на рассылку»
  (дашборд/страница + расписание + получатели + формат).
- **Безопасность:** генерировать PDF от имени получателя (или с проверкой его
  прав), чтобы не обойти RLS строк/виджетов.
- On-prem/офлайн-контур: рассылка только на внутренний SMTP МФЦ; наружу данные
  не отправлять.

### 2. Object-level ACL (ограничение доступа к объекту целиком)

**Суть.** Разграничение доступа на уровне **объекта** (подразделение/филиал/
реестр) целиком: скрыть объект и все его данные/датасеты от пользователей, кому
он не предназначен. Логическое продолжение RLS строк.

**Статус:** НЕ реализовано. Отложено.

**Причина отсрочки.** Текущая модель RLS закрывает основные сценарии МФЦ на трёх
уровнях (дашборд → виджет → строка данных по подразделению). Object-level ACL —
это ещё один, более грубый уровень («видит ли пользователь объект вообще»),
который добавляет заметную сложность (новая матрица доступа объект×субъект и её
проброс во все места чтения объектов/датасетов) при частичном пересечении с уже
готовым row-level RLS. Признано избыточным на текущем этапе.

**Известное ограничение сейчас.** Виджет **«Сравнение подразделений»
(objects_compare)** агрегирует показатель по всем объектам и **не фильтруется**
row-level RLS (это кросс-объектный управленческий срез). Если потребуется скрыть
чужие филиалы даже в этом виджете — это и есть задача object-level ACL.

**Предусловия/что нужно решить перед реализацией.**
- Модель назначения: доступ к объекту по роли и/или по подразделению
  пользователя (аналогично `data_row_acl`, но на объект).
- Opt-in или по умолчанию: объект виден всем, пока не заведено ограничение
  (как row-level), либо закрытая модель.
- Поведение привилегированных ролей (admin/moderator видят все объекты).

**Заметки по реализации (когда понадобится).**
- Заготовка ABAC (миграция 005: `attribute_assignments`/`access_policies` со
  `scope='dashboard'/'metric'/...`) может служить основой, но проще —
  отдельная таблица `object_acl(object_id, department_id|role_id)` по образцу
  `data_row_acl`.
- Точки применения: список объектов (`GET /objects`), чтение папок/документов
  объекта, `objects_compare`, авто-сборка дашборда из объекта, выпадашки выбора
  объекта/датасета.
- Обязательно fail-closed для непривилегированных без назначения.

## Что делать администратору при появлении предусловий

- **Появился SMTP МФЦ** → вернуться к разделу 1: собрать параметры, согласовать
  список рассылок, реализовать cron-рассылку на arq с уважением RLS.
- **Потребовалось скрывать объекты целиком** → вернуться к разделу 2: согласовать
  модель назначения и реализовать object-level ACL по образцу `data_row_acl`.
