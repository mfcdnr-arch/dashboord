СТРАТЕГИЧЕСКИЕ ПРИОРИТЕТЫ (добавлено 2026-07-31)

Главная сверхзадача проекта — МАКСИМАЛЬНАЯ АВТОМАТИЗАЦИЯ:

• Развёртывание — минимум ручных шагов (в идеале одна команда), автоматические миграции, генерация секретов, проверка окружения.
• Управление — администратор и пользователи управляют системой через UI, без ручных правок конфигов/SQL/консоли.
• Максимально ГРАФИЧЕСКОЕ управление — каждая административная и пользовательская операция должна быть доступна через визуальный интерфейс, а не через код/CLI/файлы.
• Самодиагностика и самолечение — система должна сама обнаруживать проблемы (health-check, мониторинг, аномалии) и по возможности исправлять их автоматически: перезапуск сервисов, откат неудачной миграции, восстановление из бэкапа, автоматическое исправление типовых ошибок при установке.
• Лёгкое расширение — архитектура должна позволять добавлять новые функции, модули, виджеты, показатели в ходе эксплуатации без рискованной «хирургии» в существующем коде (модульность, конструкторы, версионирование, feature flags там, где уместно).

ПРОЕКТ КОРОТКО

• Dashboard (`dashbord`) — корпоративная BI-платформа для ГБУ «МФЦ ДНР»: загрузка первичных документов (Excel/CSV/PDF/Word) → разметка листа → выпуск датасетов → метрики с прозрачными формулами → дашборды → модерация публикации → экспорт (Excel/PDF/PNG). Целевая среда — Astra Linux SE / ВМ / LAN, часто офлайн: всё разворачивается локально, без внешних SaaS.
• Стек: React 18 + TypeScript + Vite, ECharts — фронт, его отдаёт nginx (он же прокси API); Python 3.12, FastAPI, asyncpg (явный SQL, без ORM), JWT — бэкенд; PostgreSQL 16, Redis (кэш и очередь arq), MinIO (файлы документов); фоновые задачи — arq-воркер.
• Где что: `backend/app/modules/<домен>/` — модули API, `backend/tests/` — тесты, `frontend/src/` — SPA, `db/migrations/NNN_*.sql` — миграции, `docs/` — документация, `*.sh` в корне — установка, деплой, бэкап, сторожа. Подробно — `README.md`.
• Команды:
  – стек разработки: `docker compose -p dashbord up -d`, миграции — `sh db/run-migrations.sh`, API — `scripts/dev-api.sh` (http://127.0.0.1:8080), фронт — `cd frontend && npm run dev` (http://localhost:3080);
  – тесты бэкенда — только `docker compose -p dashbord run --rm tests` (НЕ `docker exec dashbord_api pytest`: там старая копия тестов), линтеры — `docker compose -p dashbord run --rm tests sh -lc 'ruff check . && mypy'`;
  – фронт перед коммитом: `cd frontend && npx tsc --noEmit && npm test && npm run build`.
• Текущее состояние, решения заказчика и планы — в памяти проекта; история изменений — в `docs/ЖУРНАЛ.md`.
