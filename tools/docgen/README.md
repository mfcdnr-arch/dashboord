# Генератор документации Dashboard (.docx с реальными скриншотами)

Пересобирает 5 документов в `docs/`: Паспорт системы, Установка и настройка,
Руководства администратора / модератора / пользователя.

## Предпосылки
- Запущенный dev-стек (`docker compose -p dashbord up -d`) и dev-фронт на :3080
  (vite, прокси на :8080); учётка `admin/admin`.
- Node 18+. Зависимости (один раз, в этой папке):
  `npm install docx playwright docx-preview jszip --no-save && npx playwright install chromium`

## Порядок
0. Разделы, вышедшие после 31.07.2026 (витрины, обращения, кабинет, папки,
   аномалии, подсказки виджетов/метрик, ретенция в UI), снимаются отдельным
   скриптом — им нужны свои временные данные:
   `python3 prepare_data.py && node shoot_sections.js` (в конце — `python3 prepare_data.py --cleanup`
   и SQL-подчистка, который он печатает). Кадры кладутся в тот же `shots/`.
   Скрипт `append_sections.py` нужен ТОЛЬКО чтобы дописать эти главы в уже
   собранные .docx без полной пересборки; при обычном прогоне он не нужен —
   главы уже описаны в `doc_*.js`.
1. `node shoot_all.js` — снимет базовые ~48 скриншотов в `shots/` (сам создаёт и
   удаляет временные учётки ztest_mod/ztest_user и временный архив-слепок;
   в конце БД чистая — скрипт печатает ALL DONE).
1b. `node shoot_v2.js` — метрики, список и просмотр дашборда, «О дашборде»,
   режим раскладки, объекты, выпуски, меню зрителя (снимаются на РЕАЛЬНЫХ
   данных стенда, свои временные данные не нужны).
1c. `node shoot_v3.js` — разделы 12–17.08: фильтр периода (в том числе состояние
   «за период отчётов нет»), меню «куда дальше», «⚑ проблема», аналитика папки,
   «Руководителю».
1d. `node shoot_v4.js` — два кадра обратной связи: карточка обращения с
   контекстом и запрос доступа глазами зрителя. Скрипт САМ заводит временное
   обращение и САМ его убирает; нужна учётка `viewer1` с доступом хотя бы к
   одному дашборду.
2. `node doc_user.js && node doc_moderator.js && node doc_admin.js && node doc_install.js && node doc_passport.js`
   → готовые .docx в `out/`.
3. Проверка рендера: `node preview.js out/<файл>.docx имя` → PNG-страницы в `out/`.
4. Скопировать .docx в `../../docs/`, закоммитить, пересобрать архивы поставки
   (`git archive --prefix=Dashbord/ -o Final_v.1.tar HEAD`, аналогично zip).

Правило проекта: документация обновляется в день изменения функционала.

## Тех-уроки (зашиты в скрипты — не ломать)
- SQL в psql передаётся через **stdin** (bcrypt-хэш содержит `$`, argv через shell его портит).
- Клик по строкам списков — `page.evaluate` по «самому глубокому элементу,
  содержащему текст»: названия — текст-ноды среди span'ов, точного leaf нет.
- Возврат из открытого дашборда к списку — **хлебной крошкой**, nav-кнопка
  раздела состояние не сбрасывает.
- `img('имя')` падает с ENOENT, если кадра нет: ссылаться в главах только на
  реально снятые кадры (или фильтровать через `fs.existsSync`, как сделано для
  шагов мастера).
- Ответ `GET /dashboard-pages/{id}/widgets` — ОБЪЕКТ `{page_id, widgets:[…]}`,
  а не массив.
- В doclib children проходят `.flat(Infinity)` — незаспредленный массив иначе
  даёт битый XML (`<0/>`).
